## 3. 缺口与技术债清单（按优先级）

### G1 · 原子性严格性缺口（中，已实测复现）

`ExecutionContext.apply_mutations()` 是公开方法，函数可中途手动提交，后续 fail 无法回滚已提交部分：

```python
def execute(ctx):
    ctx.set(ref, "x", 1)
    ctx.apply_mutations()   # 已生效
    ctx.set(ref, "x", 2)
    ctx.fail("boom")        # x=1 残留，违反 §31
```

实测结果：`x = 1`（严格原子应为 0）。
**建议**：将 `apply_mutations` 从公开 API 收敛（改名 `_commit` 或仅允许 Executor 调用一次）；或 Runtime 在 executor 返回后统一 apply，函数侧禁止提交。

### G2 · invoke 错误路径不对称（中）

前置校验（FunctionNotFound/InvalidArgument/ObjectNotFound）**raise**，执行期错误进 **result.error**。嵌入方若只检查 `result.error` 会漏掉前置异常。
**建议**：统一为"invoke 永不 raise，错误一律进 result.error"；或在 FunctionResult 增加 `phase` 字段。当前 CLI/HTTP 已双路处理，不影响 Demo，但影响嵌入体验。

### G3 · SQLite find 全表扫描（低）

`find_objects` 加载该类型全部行后 Python 过滤，未下推 SQL WHERE。v0.1 可接受；数据量增长后需按 `otype` 索引 + 简单操作符下推。

### G4 · HTTP 状态码精确类型匹配（低）

`_STATUS.get(type(exc))` 不做 isinstance 匹配，未来新增 KernelError 子类会误判为 400/500。改为 isinstance 遍历即可。

### G5 · 工程卫生（中，一次性清理）

- **不是 git 仓库**：无版本控制、无历史
- 无 `.gitignore`；`src/ontology_runtime.egg-info/`、`.pytest_cache/`、`__pycache__` 构建产物散落
- Windows 控制台中文乱码（GBK vs UTF-8，环境问题）：demo/agent 可加 `sys.stdout.reconfigure(encoding="utf-8")`

### G6 · 测试覆盖缺口（低）

- MCP Adapter 仅有 `list_tools` smoke test，无 invoke/get 端到端调用测试
- HTML Demo 无自动化验证（`ui_initial.png` 为人工验证痕迹）
- SQLite 并发（threading.Lock）无测试
- loader 的 namespace/version 字段无边界测试
